El piloto web permite iniciar sesión, registrarse y editar con cuentas de administrador. Cada sección incluye **Agregar**; el lápiz abre los campos del bloque. Los cambios se guardan como borrador local privado por usuario y solo aparecen para visitantes al pulsar **Publicar**. Se conservan hasta 100 versiones publicadas, y se pueden preparar restauraciones desde el historial. Si otro administrador publicó entretanto, el servidor rechaza la publicación para evitar sobrescribir sus cambios.

Activación desde iPad: abre [activar.html](https://adolfoacr.github.io/Balcon-del-Zocalo/activar.html), copia el SQL de `supabase/setup.sql` y ejecútalo en el SQL Editor de tu proyecto. Configura Site URL y Redirect URLs, registra y confirma el correo de la cuenta propietaria y ejecuta `select public.bootstrap_site_owner('TU_CORREO');` desde SQL Editor. Este último paso requiere el propietario del proyecto: una clave pública no permite crear tablas ni asignar el primer administrador. No se debe sustituir la clave del navegador por service_role.

El propietario puede conceder o retirar permisos a otras cuentas registradas y confirmadas desde Usuarios y cuenta. También puede asignar una sola cuenta al chef Checo; esa cuenta obtiene permisos de administrador y es la única que puede seleccionar propuestas. Las cuentas nuevas son visitantes; no se confía en metadatos de registro ni en flags de localStorage para los permisos. Las comprobaciones definitivas las ejecuta PostgreSQL con RLS y funciones de permisos restringidos.

**Comparte tu trabajo** permite a cuentas confirmadas enviar investigaciones o desarrollos, con título, resumen, cuerpo, referencia HTTPS y hasta tres adjuntos de 10 MB. Cada participante ve solo sus propuestas y la respuesta de Checo. El equipo administrador puede consultar todas; únicamente Checo puede cambiar su estado. Los adjuntos se guardan en `work-files`, un bucket privado, y se abren mediante enlaces firmados que caducan en cinco minutos. Los trabajos no se publican automáticamente ni se envían por correo. La selección abre una posible colaboración, sin prometerla a todos los participantes.

Los archivos de banners, fotos y el libro publicado se guardan en `site-media`, público. El PDF que importa un visitante para probar el lector permanece local. Supabase permite confirmar y recuperar cuentas por correo; el proyecto debe configurar URLs de redirección y un proveedor SMTP adecuado para usuarios reales. El piloto usa sesiones en sessionStorage (por pestaña), sin guardar contraseñas; realiza refresh y verificación de cuenta. La base de datos, los adjuntos y el sitio publicado funcionan entre dispositivos después de activar el esquema. Los borradores sin publicar, favoritos y PDFs personales siguen siendo locales.

Validación: Playwright usa una API de pruebas para recorrer la interfaz sin crear cuentas reales; PGlite ejecuta PostgreSQL para comprobar políticas, asignación de roles, conflictos de publicación, aislamiento de propuestas y selección exclusiva por Checo. Esto no sustituye una prueba integral contra el Supabase real una vez instalado el esquema. La app nativa SwiftUI no incorpora todavía este editor; la implementación comprobada corresponde al piloto web.

Para regenerar la entrega: `npm run build` y `node scripts/build-setup.mjs`. Para comprobar reglas: `npm run test:security`; para interfaz: `npm test`; para dimensiones: `npm run check:responsive`.
